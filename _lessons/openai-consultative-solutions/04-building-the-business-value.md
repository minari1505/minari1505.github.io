## 학습 목표

- OpenAI 기회 대화에서 **비즈니스 가치**가 어디에 들어가는지 설명하기
- 워크플로 문제를 **비즈니스 결과**와 **필요한 증거**에 연결하기
- 증거 기반 **가치 가설(value hypothesis)** 세우기
- 측정 가능한 지표와 **방향성 이익 추정(directional benefit estimate)** 정하기
- 이해관계자별 **고객 맞춤 가치 내러티브** 만들기

## 한눈에 보는 코스 흐름

<ol class="oa-flow">
  <li><strong>AI 역량</strong>무엇을 할 수 있나</li>
  <li><strong>워크플로</strong>어떤 업무에 붙나</li>
  <li><strong>유스케이스</strong>구체적으로 무엇이 바뀌나</li>
  <li><strong>비즈니스 가치</strong>왜 중요하고, 어떤 증거가 있나</li>
  <li><strong>파트너 행동</strong>다음에 무엇을 검증하나</li>
</ol>

이 코스의 목표는 **최종 ROI 모델이 아니라**, 고객이 "다음에 검증할 가치가 있나?"를 판단할 수 있는 **믿을 만한 가치 스토리**를 만드는 거예요.

## 1. 비즈니스 가치는 어디에 들어가나

<div class="oa-eli">
  <span class="oa-eli__head">🚲 쉽게 말하면</span>
  <p>부모님께 "새 자전거 사 주세요!"보다 "학원까지 버스로 40분인데 자전거면 15분이라, <b>매일 50분을 숙제에 쓸 수 있어요</b>. 일주일만 빌려 타 보고 정말 그런지 확인해 볼게요"가 훨씬 설득력 있죠. 기능(자전거)이 아니라 <b>업무 문제 → 개선 → 결과 → 증거 → 다음 단계</b>로 말하는 거예요.</p>
</div>

**유스케이스**는 AI가 고객을 도와 할 수 있는 일을, **가치 스토리**는 그 유스케이스를 **왜** 추진할 만한지를 설명해요. "지원 지식에 AI를 쓰고 싶어요"는 좋은 방향이지만 아직 가치를 설명하진 못해요. 가치가 없으면 대화는 "요약돼요? 질문에 답해요? 시간 아껴 줘요?" 같은 **기능 질문**에 머물러요.

### 셀러용 가치 쌓기 순서

고객에게 이름 붙여 발표할 프레임워크가 아니라, **생각을 정리하는 가이드**예요. "AI가 도움 돼요"에서 "ROI가 날 거예요"로 바로 점프하지 않게 해 줘요.

| 단계 | 명확히 할 것 | 셀러 질문 |
|---|---|---|
| **워크플로 문제** | 지금 어렵고·느리고·비싸고·들쭉날쭉하고·위험하고·확장 어려운 것 | 고객은 현재 업무에서 무엇에 애를 먹나? |
| **AI 기반 개선** | OpenAI 역량으로 나아질 수 있는 것 | 일의 어느 부분이 더 빠르고·좋고·일관되고·쉬워질까? |
| **운영 결과** | 측정 가능한 변화 | 어떤 지표·행동·관찰 결과가 나아질까? |
| **비즈니스 우선순위** | 그 결과가 고객에게 왜 중요한가 | 어떤 목표·압박·우선순위를 돕나? |
| **검증 증거** | 가치를 믿을 만하게 만드는 것 | 다음에 어떤 데이터·예시·의견을 확인할까? |

<div class="oa-eli">
  <span class="oa-eli__head">💬 순서대로 말하면 (지원 운영 예시 요약)</span>
  <p>"상담원이 응답 전 여러 정책 소스를 뒤져요(<b>문제</b>). AI 기반 워크플로가 정책 안내를 더 빨리 찾고 종합하게 도우면(<b>개선</b>) 검색 시간 감소, 답변 일관성 향상, 불필요한 에스컬레이션 감소가 가능할 수 있어요(<b>결과</b>). 고객이 운영 부담을 통제하며 지원 경험을 높이려 하기 때문에 중요해요(<b>우선순위</b>). 다음엔 기준 검색 시간, 에스컬레이션율, 답변 품질 기대치, 대표 케이스를 검증해요(<b>증거</b>)."</p>
</div>

이 단계에선 제품 경로를 비교하거나 솔루션을 설계하지 않아요. 가치 실현 방식을 설명하는 데 도움 될 때만 가볍게 언급해요 (제품 설명은 강의 기준).

  <div class="oa-card"><span class="oa-card__icon">💬</span><span class="oa-card__title">ChatGPT Chat</span>생각·조사·초안·분석·다듬기를 함께</div>
  <div class="oa-card"><span class="oa-card__icon">🗂️</span><span class="oa-card__title">ChatGPT Work</span>더 긴 다단계 지식 업무 위임, 승인된 앱·파일을 맥락으로, 사람이 방향을 잡고 중요한 행동 승인</div>
  <div class="oa-card"><span class="oa-card__icon">🧱</span><span class="oa-card__title">API</span>제품·시스템·워크플로·고객 경험에 지능을 내장</div>

  <div class="oa-card"><span class="oa-card__icon">👤</span><span class="oa-card__title">개인 dots</span>Work 안에서 범위가 정해진 지속 책임 수행. 공동 검토·유지 책임이 필요한 팀 소유 프로세스와는 다름</div>
</div>

오픈 웨이트 모델·마이그레이션·하이브리드 경로는 검증된 요구사항이 자체 인프라·커스터마이징을 가리킬 때 관련될 수 있어요. 쓸 만한 문장: **"솔루션 경로는 아직 검증이 필요하지만, 가치 가설은 이 워크플로 개선이 고객의 [구체적 결과]를 도울 수 있다는 것입니다."**

## 2. 워크플로 변화를 비즈니스 결과에 연결하기

### 가장 중요한 결과 하나를 고르기

빠른 지원 답변 검색은 응답 시간, 에스컬레이션, 상담원 역량, 답변 일관성, 고객 경험을 모두 도울 수 있어요. 다 사실일 수 있어도 **같은 무게로 내세우면 안 돼요.** 고객이 실제로 언급한 우선순위, 신경 쓰는 이해관계자, 영향받는 지표·압박, 고객이 "검증해 볼 만하다"고 결정할 이유를 물어요.

<div class="oa-vs">
  <div class="oa-vs__bad">
    <span class="oa-vs__label">🎈 약한 가치 스토리</span>
    <ul>
      <li>가능한 이점을 전부 주장</li>
      <li>"AI 어시스턴트", "에이전트" 같은 라벨로 시작</li>
    </ul>
  </div>
  <div class="oa-vs__good">
    <span class="oa-vs__label">🎯 강한 가치 스토리</span>
    <ul>
      <li>고객 우선순위·증거에 가장 맞는 결과 하나로 시작</li>
      <li>누가, 무엇을 만들고, 어디서 막히는지부터</li>
    </ul>
  </div>
</div>

"계약 검토용 AI" 하나도 검토 주기 단축, 외부 로펌 비용 절감, 조항 일관성, 상업 위험 감소, 현업 셀프서비스, 법무팀의 복잡 업무 집중 등 **전혀 다른 가치 스토리**를 숨기고 있어요.

### 결과 영역 — 체크리스트가 아니라 힌트 메뉴

| 결과 영역 | 워크플로 대화에서의 의미 | 찾아볼 증거 예 |
|---|---|---|
| 매출 성장·매출 역량 | 더 가치 있는 일을 추진·처리·전환 | 전환율, 적격 물량, 파이프라인 진척, 셀러 역량 |
| 비용 절감·불필요한 지출 회피 | 유료 자원 덜 쓰거나 외부 지출 회피 | 건당 비용, 외부 지출, 재작업 비용 |
| 생산 역량 증가 | 반복 업무 ↓, 고가치 업무 ↑ | 검토 시간, 수작업 횟수, 처리 건수, 대기열 |
| 속도·주기 단축 | 일이 더 빨리 흐름 | 주기 시간, 처리 시간, 대기 시간, 백로그 나이 |
| 품질·일관성 | 더 완전·정확·일관·정책 부합 | 오류율, 재작업률, 일관성, 품질 검토 결과 |
| 위험 감소·통제 | 문제를 더 일관되게 식별·예방·에스컬레이션 | 감사 지적, 에스컬레이션율, 정책 예외 |
| 고객 경험 | 더 빠르고 명확하고 일관된 서비스 | 응답 시간, 해결률, 만족도, 불만율 |
| 직원 경험 | 답답하고 가치 낮은 일 감소 | 업무량 피드백, 반복 업무 시간, 번아웃 지표 |

### 이해관계자 신호에 맞춰 강조점 정하기

| 고객이 이렇게 말하면 | 이걸 앞세워요 |
|---|---|
| "백로그를 줄여야 해요." | 처리량, 주기 시간, 대기열 크기, 역량 |
| "비용 압박이 있어요." | 단위 업무당 비용, 회피 지출, 수작업, 비용 전환 가정 |
| "감사 지적을 받았어요." | 위험 통제, 정책 준수, 일관성, 에스컬레이션 품질, 증거 기록 |
| "팀이 과부하예요." | 직원 노력, 인수인계, 반복 업무, 고가치 업무 역량 |
| "고객이 너무 오래 기다려요." | 응답 시간, 해결률, 에스컬레이션율, 고객 경험 |

### 예시 — 금융사의 느린 리스크 검토

리스크 분석가가 케이스 문서를 검토하고, 이슈를 찾고, 요약 메모를 쓰고, 추가 검토 건을 에스컬레이션해요. 백로그가 쌓이고, 리더는 **검토 일관성과 감사 대비**를 걱정해요.

  <div class="oa-card"><span class="oa-card__icon">🚀</span><span class="oa-card__title">속도</span>케이스 검토 주기 단축</div>
  <div class="oa-card"><span class="oa-card__icon">🧑‍💼</span><span class="oa-card__title">역량</span>분석가가 고가치 검토에 쓸 시간</div>
  <div class="oa-card"><span class="oa-card__icon">🎯</span><span class="oa-card__title">품질</span>더 일관된 요약과 의사결정 지원</div>
  <div class="oa-card oa-card--warn"><span class="oa-card__icon">🛡️</span><span class="oa-card__title">위험</span>백로그 감소, 감사 대비 강화</div>

**감사 압박**이 경영진 우선순위라면 위험·일관성·증거 품질·검토 통제를, **운영 백로그**가 우선이라면 주기 시간·처리량·분석가 역량을 앞세워요. 파일럿을 준비한다면 월 케이스량, 건당 검토 노력, 백로그 크기, 검토 주기, 품질 검토 결과, 에스컬레이션율, 사람 감독 요건을 모아요.

## 3. 증거 기반 가치 가설 세우기

**가치 가설**은 선택한 결과를 **검증 가능한 문장**으로 바꾼 거예요. 최종 주장도, 보장도, ROI 모델도 아니에요.

> **가설 틀:** "**[현재 워크플로 문제]**가 **[이해관계자·비즈니스 결과]**에 영향을 주기 때문에, AI로 **[워크플로 단계·결과물]**을 개선하면 **[기대되는 측정 가능한 개선]**에 도움이 될 수 있고, 이는 **[고객 우선순위]** 때문에 중요하다."

<div class="oa-eli">
  <span class="oa-eli__head">📝 예시 가설 (요약)</span>
  <p>"리스크 분석가가 건당 몇 시간씩 문서 검토와 메모 작성에 쓰기 때문에, AI 지원 요약·메모 초안이 <b>분석가 감독을 유지하면서</b> 검토 노력과 백로그를 줄일 수 있다. 고객이 감사 주기를 단축하고 일관성을 높여야 하는 압박을 받고 있어서 중요하다."</p>
</div>

### 증거와 가정을 분리하기 — 신뢰도 점검

<div class="oa-vs">
  <div class="oa-vs__good">
    <span class="oa-vs__label">📌 증거 (이미 알거나 확인 가능)</span>
    <ul>
      <li>업무 물량, 현재 노력·비용, 주기 시간</li>
      <li>오류·재작업·에스컬레이션율</li>
      <li>이해관계자 우선순위, 기존 운영 지표</li>
      <li>고객 제공 예시, 대표 문서, 현재 워크플로 오너</li>
    </ul>
  </div>
  <div class="oa-vs__bad">
    <span class="oa-vs__label">❓ 가정 (사실일 수 있지만 증명 필요)</span>
    <ul>
      <li>도입 수준, 기준 성과, 데이터 가용성</li>
      <li>사람 검토 필요, 배포 복잡도, 변화 관리 노력</li>
      <li>절약된 시간이 비용 절감·역량·서비스 품질·위험 감소 중 <b>무엇으로 바뀔지</b></li>
    </ul>
  </div>
</div>

**고객 사례를 증거로 쓸 때**도 종류를 구분해요.

| 증거 종류 | 의미 | 주의 |
|---|---|---|
| **관찰된 결과** | 직접 확인한 출력·측정치, 과제·조건 기록 | 가장 강하지만 조건을 함께 남기기 |
| **고객 보고 결과** | 고객이 자기 테스트·경험을 말한 것 | 출처·표본 크기·한계 유지, **독립 검증된 것처럼 말하지 않기** |
| **제안된 이익** | 다른 워크플로·고객에게 가능할 수 있는 개선 | 그 고객의 기준선과 파일럿 증거가 생기기 전까진 **가설** |

> **문장 패턴:** "우리가 가진 증거는 **[증거]**입니다. 현재 가정은 **[가정]**입니다. 다음 검증 단계는 **[모을 증거]**입니다."

반복 업무라면 **한 번 성공한 실행**이 안정적인 제공이나 지속 노력을 증명하지 않아요. 반복 실행으로 테스트해야 해요.

### 근거 없는 가치 주장이 대화를 약하게 만드는 이유

<div class="oa-cards">

## 4. 영향 측정과 방향성 이익 추정

### 가치 스토리를 뒷받침하는 것만 측정

모든 걸 재는 게 목표가 아니에요. **규칙: 지표가 가치 스토리 검증에 도움이 안 되면 앞세우지 않는다.**

| 비즈니스 결과 | 고려할 지표 |
|---|---|
| 속도 | 주기 시간, 처리 시간, 대기 시간, 백로그 나이 |
| 생산성·역량 | 수작업 노력, 처리 건수, 검토 시간, 대기열 |
| 비용 | 외부 지출, 재작업 비용, 건당 비용, 채용 회피 |
| 품질 | 오류율, 재작업률, 일관성, 품질 검토 결과 |
| 위험 | 에스컬레이션율, 감사 지적, 정책 예외, 위험 플래그 |
| 고객 경험 | 응답 시간, 해결률, 만족도, 불만율 |
| 직원 경험 | 업무량, 만족도, 반복 업무 시간 |

에스컬레이션 감소가 목표라면 검색 시간만으론 부족하고 에스컬레이션율, 불필요한 에스컬레이션 비중, 답변 품질 기대치, 에스컬레이션당 노력도 필요해요. **처리 시간 단축**을 주장한다면 합의된 시작점부터 **리뷰어가 수용한 결과**까지 대기·재시도·수정을 포함해 재요. 주된 지연이 승인이나 정보 누락이라면 생성이 빨라져도 워크플로는 안 빨라질 수 있어요.

### 아직 추정하지 말아야 할 때

입력이 대부분 추측이면 숫자가 실제보다 **확실해 보이게** 만들어요. 이럴 땐 계산 대신 **빠진 입력을 다음 검증 단계로** 만들어요.

- 업무 물량을 모름 / 현재 노력·비용을 모름
- 기대 개선 폭이 고객 입력 없는 추측
- 비즈니스 결과가 불분명 / 어떤 문제가 가장 중요한지 합의 안 됨
- 추정이 더 중요한 discovery를 방해함

> "다음 단계는 잠재 영향을 추정하는 데 필요한 **기준선 증거를 모으는 것**입니다." — 이것도 충분히 강한 가치 대화예요.

### 방향성 이익 ≠ ROI

ROI라고 부르려면 솔루션 비용, 구현·통합 비용, 교육·도입·변화 관리 비용, 기간, 기대 도입률, 기준 성과, **절약 시간의 전환 경로**, 지속 운영·지원 비용, 위험 조정과 신뢰 수준이 필요해요.

<div class="oa-eli">
  <span class="oa-eli__head">⏳ 절약된 시간 ≠ 절약된 돈</span>
  <p>숙제가 30분 일찍 끝났다고 용돈이 늘진 않죠. 그 30분을 운동에 쓸지, 게임에 쓸지, 학원을 하나 줄일지에 따라 "가치"가 달라져요. 회사도 절약 시간을 더 많은 케이스 처리, 서비스 품질, 백로그 감소, 매출 역량, 채용 회피, 외부 지출 감소, 통제 강화, 전문가의 고가치 업무 중 <b>어디에 쓰느냐</b>에 따라 필요한 증거가 달라요. 비용 절감이 되려면 계약직·외부 로펌·초과 근무·채용 계획이 <b>실제로 줄어야</b> 해요.</p>
</div>

| 가진 것 | 보통 말할 수 있는 것 | 아직 말하면 안 되는 것 |
|---|---|---|
| 업무 물량 + 현재 소요 시간 | "절약 역량이 될 수 있어요." | "비용 절감이에요." |
| 현재 비용 + 검증된 개선 가정 | "잠재적 총이익이 될 수 있어요." | "최종 ROI예요." |
| 비용·도입·기간·구현 노력·가치 전환 가정 | "ROI 모델을 뒷받침할 수 있어요." | 모델 검증 전 "ROI가 입증됐어요." |

### AI 지원 업무의 전체 비용 따지기

출력을 **생성하는 비용**이 아니라 **쓸 만한 결과를 전달하는 전체 비용**을 봐요. 토큰 사용이 줄면 비용 요소 하나가 줄 뿐, 총 과제 비용이나 실현된 절감을 증명하지 않아요.

- **API 비용 추정**: 기술 담당자가 대표 과제의 모델·도구 사용량을 측정하고, 테스트한 설정에 적용되는 가격으로 계산하며, **가격 출처와 날짜를 기록**해요. API 사용료는 ChatGPT Work나 Codex 구독 가격과 **별개**예요.
- **모델·속도 선택** (강의 기준): GPT-6.1 Sol과 GPT-6 Astra는 Work·Codex·API에서 평가할 수 있고(일반 Chat 모델 비교가 아님), Standard·Fast·자격 있는 Ultrafast 옵션은 사용량·가용성 조건이 달라요. 같은 일과 품질 기준으로 실제 모델·모드·요금제·처리 지역·날짜 있는 가격을 비교하고, **모든 모델이 모든 모드를 지원한다고 가정하지 않아요.**
- **비용 부담자** (강의 기준): 참여 앱에서 개인 ChatGPT 사용량을 쓰는 건 선택 사항이며 로그인 신원·앱 요금과 별개예요. Team Tasks는 워크스페이스 크레딧, API는 별도 청구. **기존 구독을 공짜 역량으로 취급하지 마세요.**
- **구매 경로** (강의 기준): OpenAI Marketplace 자격은 고객·제품·구매에 따라 달라요. 고객은 파트너와 직접 계약·결제하고 적격 구매는 OpenAI 약정과 정산돼요. **목록 등재만으로 자격·할인·총비용 절감이 확정되지 않아요.**

### 추정치로 다음 영업 행동 만들기

숫자 자체보다 **그 숫자가 만드는 다음 대화**가 가치예요. 가장 강한 입력은? 가장 약한 입력은? 추정을 가장 크게 바꿀 가정은? 기준선은 누가 갖고 있나?

| 추정이 보여 주는 것 | 셀러 행동 |
|---|---|
| 이익이 의미 있고 증거도 꽤 강함 | 워크플로 오너와 기준선 확인, 더 깊은 검증 준비 |
| 이익은 의미 있지만 증거가 약함 | 물량·노력·비용·도입·품질 가정을 먼저 모으기 |
| 이익이 작아 보임 | 시간 더 쓰기 전에 워크플로 범위·결과·우선순위 재검토 |
| 큰 가정 하나에 좌우됨 | 그 가정을 명확히 이름 붙여 **다음 검증 단계로** |

### 예시 — 정책 에스컬레이션 줄이기

두 가지 방향성 추정 공식을 쓸 수 있어요 (입력은 고객이 검증한 값으로).

```text
잠재 절약 검색 역량 = 월 케이스 수 × 건당 현재 검색 시간 × 기대 검색 시간 단축률
잠재 회피 에스컬레이션 노력 = 월 케이스 수 × 현재 에스컬레이션율 × 회피 가능 비중 × 에스컬레이션당 노력
```

둘 다 **ROI가 아니에요.** 다음 검증: 기준 검색 시간, 에스컬레이션 정의, 답변 품질 기대치, 도입 가정, 데이터 접근, 워크플로 오너 우선순위, 사람 검토·승인 필요.

## 5. 고객 맞춤 가치 내러티브

**가치 내러티브**는 고객 이해관계자가 **되풀이할 수 있는 짧은 버전**이에요. 피치 대본도, 최종 비즈니스 케이스도, 제품 추천도 아니고, **왜 검증할 만한지**에 대한 간결한 설명이에요. 너무 넓으면 스폰서가 못 옮기고, 너무 기술적이면 비즈니스 청중이 놓치고, 너무 일찍 재무적이면 검증 안 된 가정을 공격받아요.

### 이해관계자별로 강조점만 바꾸기 (사실은 그대로)

| 이해관계자 | 강조점 |
|---|---|
| **CFO** | 재무 노출, 비용, 생산성, 투자 가정, 이익 추정의 신뢰도 (+ 사용료 부담·총비용) |
| **COO** | 처리량, 주기 시간, 운영 부담, 서비스 품질 |
| **CIO/CTO** | 확장성, 통합 적합성, 거버넌스, 데이터 접근, 운영 통제 |
| **워크플로 오너** | 일상 사용성, 품질, 도입, 인수인계, 노력 감소 |
| **경영 후원자** | 전략 우선순위, 긴급성, **안 했을 때의 위험**, 비즈니스 영향 |

### 포트폴리오를 의식하되 솔루션 라우팅은 하지 않기

솔루션 경로가 검증되지 않았다면 **"OpenAI 기반 워크플로 개선…"** 같은 중립 표현을 써요. 그럴듯한 경로가 있다면 가치 설명을 돕는 정도로만 이름을 붙여요 (예: 승인된 앱·파일을 쓰는 ChatGPT Work 워크플로, 지원 앱에 내장하는 API 기반 워크플로, 사람 검증을 유지한 Codex 워크플로 — 강의 기준). 제품 비교, 구현 선택, 아키텍처 주장은 이 단계에서 하지 않아요.

| 셀러 진술 | 초점 |
|---|---|
| 가치 가설 | 어떤 결과가 왜 나아질 수 있나 |
| 솔루션 방향 | 이미 알려졌다면, 가치가 실현될 법한 방식 |
| 검증 필요 | 다음에 필요한 증거·제약·인수인계 |

### 예시 — 주간 계정 브리핑

| 요소 | 내용 |
|---|---|
| 고객 우선순위 | 운영 부담을 늘리지 않고 계정 준비 개선 |
| 워크플로 문제 | 갱신 대화 전 승인된 소스에서 업데이트를 반복 수집 |
| AI 유스케이스 | 출처 표시와 미해결 정보 표시가 있는 **주간 계정 브리핑** 준비 → 고객 접촉 전 계정 담당자가 검토 |
| 가능한 결과 | 쓸 수 있는 준비 역량 증가, 더 일관된 계정 커버리지 |
| 방향성 영향 | 수집 노력이 줄면 역량이 생길 수 있지만, **쓸 만한 브리핑이 필요한 때 검토자에게 도착해야** 가치 있음 |
| 알려진 증거 | 워크플로 오너 확인, 대표 준비 예시 제공 가능 |
| 검증할 가정 | 기준 준비·검토 시간, 결과 수용, 소스 접근, 반복 유지 노력, 자격 있는 비용 부담자·구매 방식 — **아직 확정된 절감 없음** |
| 다음 검증 | 대표 주간 사이클을 현재 방식과 비교. 오너는 품질·총 준비 노력, 기술·상업 담당자는 실패 실행 포함 운영 비용·자금 가정 확인 |

- **운영 리더용**: "검토된 주간 브리핑이 반복 준비 노력을 줄이고 커버리지를 높일 수 있어요. 절약 역량을 추정하기 전에, 검토 시간과 입력이 불완전했던 주까지 포함해 수용된 브리핑을 현재 방식과 비교해요."
- **기술 리더용**: "같은 가치 가설이지만 안정적인 접근과 유지 가능한 반복 프로세스에 달려 있어요. 워크플로 테스트와 함께 연결 소유권, 운영 노력, 사용료 부담을 확인해요."

→ **같은 사실, 다른 강조점.**

## 정리

- 가치 스토리는 **AI 역량 → 워크플로 → 유스케이스 → 비즈니스 가치 → 파트너 행동**으로 쌓아요. "AI가 시간을 아껴요"로 시작하지 않아요.
- 가능한 이점을 다 늘어놓지 말고, **고객이 후원할 가능성이 가장 큰 결과 하나**를 증거와 함께 앞세워요.
- **가치 가설**은 검증 가능한 문장이고, **증거와 가정을 분리**해요. 고객 사례는 관찰·고객 보고·제안된 이익을 구분해서 써요.
- **방향성 추정은 ROI가 아니에요.** 절약된 시간 ≠ 절약된 돈이고, 입력이 추측뿐이면 추정 대신 빠진 입력을 다음 검증으로 삼아요.
- 비용은 토큰이 아니라 **수용된 결과를 내는 전체 비용**(재시도·검토·유지·자금 부담자 포함)으로 봐요.
- 내러티브는 **사실은 고정, 강조점만 청중에 맞게**, 그리고 마지막은 **다음 검증 단계**로 끝내요.
