## 학습 목표

- CCA-F 시험의 형식(문항 수, 시간, 합격선, 채점 방식)을 알기
- 5개 출제 도메인과 배점을 외우고, 공부 시간을 어디에 쓸지 정하기
- 시나리오 문제를 풀 때 쓰는 두 가지 판단 기준을 익히기

## 먼저 한 문장으로

**CCA-F는 "Claude를 써 봤는가"가 아니라 "이 상황에서 어떤 설계를 고를 것인가"를 60문항의 시나리오로 묻는 시험입니다.**

정답을 외우는 시험이 아닙니다. 네 개의 선택지 중 셋은 그럴듯한 오답이고, 하나만 "이 조건에서 가장 알맞은" 답입니다. 그래서 왜 그게 정답이고 나머지가 오답인지 스스로 설명할 수 있어야 통과합니다.

## 시험 형식

| 항목 | 내용 |
|---|---|
| 정식 이름 | Claude Certified Architect – Foundations (CCA-F) |
| 문항 수 / 시간 | 60문항 / 120분 |
| 형식 | 시나리오 하나에 여러 객관식 문항이 붙는 구조. 4지선다, 정답 1개 |
| 시나리오 수 | 준비된 6개 중 4개가 출제. 어떤 4개인지는 응시할 때마다 다름 |
| 합격선 | 1,000점 만점 중 720점 (스케일 점수) |
| 응시료 | USD 99 |
| 언어 | 영어 |
| 응시 방식 | 온라인 프록터(집에서 응시 가능) |

두 가지를 짚어 둡니다.

**스케일 점수라서 "43문항 맞히면 합격"이 정확한 계산은 아닙니다.** 문항 난이도에 따라 가중치가 붙습니다. 모의고사를 풀 때는 43/60(약 72%)을 자가 채점 기준으로 쓰되, 실전에서는 특정 도메인만 잘 보고 나머지를 버리는 전략이 통하지 않는다고 생각하면 됩니다.

**무응답은 오답 처리됩니다.** 모르는 문제도 소거법으로 하나는 반드시 고릅니다.

## 5개 도메인과 배점

| 도메인 | 배점 | 60문항 기준 |
|---|---|---|
| 1. 에이전트 아키텍처와 오케스트레이션 | 27% | 약 16문항 |
| 2. 툴 설계와 MCP 통합 | 18% | 약 11문항 |
| 3. Claude Code 설정과 워크플로우 | 20% | 약 12문항 |
| 4. 프롬프트 엔지니어링과 구조화 출력 | 20% | 약 12문항 |
| 5. 컨텍스트 관리와 신뢰성 | 15% | 약 9문항 |

도메인 1·3·4만 합쳐도 전체의 3분의 2입니다. 다만 배점이 가장 낮은 도메인 5도 취약하면 그대로 9문항을 잃습니다. 모든 도메인에서 "평균 이상"을 목표로 잡는 편이 안전합니다.

이 코스의 레슨 2~7은 이 다섯 도메인을 순서대로 다룹니다. 이미 이 사이트의 다른 Anthropic 강의 정리에 있는 내용(API 기본 문법, MCP 서버 만들기, Claude Code 기본 조작 등)은 반복하지 않고, **시험이 판단을 묻는 지점**만 모았습니다.

## 시험 범위 밖인 것

공식 가이드가 범위 밖으로 명시한 주제가 있습니다. 여기에 시간을 쓰지 않아도 됩니다.

- 모델 파인튜닝
- 과금·인증 절차의 세부
- 벡터 DB 구현, 임베딩
- 스트리밍 구현 세부
- Computer Use, 이미지 분석
- Constitutional AI, RSP 같은 Anthropic 내부 기법
- 프롬프트 캐시의 구현 세부(1.25배, 10~20% 같은 숫자)

단, "개념"은 알아 둬야 합니다. 예를 들어 프롬프트 캐시가 뭔지, RAG가 뭔지는 선택지에 등장합니다. 구현 세부만 범위 밖입니다.

## 문제를 풀 때 쓰는 두 가지 판단 기준

교재 저자가 실전에서 점수 차이가 가장 크게 벌어진다고 짚은 지점입니다. 시나리오 문제 대부분이 이 둘 중 하나로 갈립니다.

### 1. 확률적 해법 vs 결정적 해법

- 확률적 해법: 프롬프트에 "~하지 마세요"라고 적어서 모델에게 부탁하기
- 결정적 해법: 훅, 코드 게이트, 스키마 검증으로 시스템이 막기

"반드시", "절대", "규정상"이 붙은 요구가 있으면 결정적 해법이 정답입니다. 모델은 지시를 따를 확률이 높을 뿐, 100%는 아니기 때문입니다. 예를 들어 "배포 전 테스트를 반드시 통과시켜야 한다"면 CLAUDE.md에 문장을 적는 것(A)보다 훅으로 배포 커맨드를 차단하는 것(B)이 정답입니다.

### 2. 화려한 해법 vs 최소 비용의 근본 대책

- 툴이 40개라서 선택 정확도가 떨어진다 → 툴 수를 줄이는 것이 답이지, 모델을 Opus로 바꾸는 것이 답이 아닙니다.
- 단순 분류 100만 건 → Haiku가 답이지, "최신 모델이니까 Opus"가 답이 아닙니다.
- 단일 도메인, 툴 10개짜리 작업 → 싱글 에이전트가 답이지, 멀티 에이전트가 답이 아닙니다.

과잉 설계를 피하는 쪽이 정답인 경우가 많습니다.

## 시나리오 읽는 법

선택지를 보기 전에 시나리오에서 제약 조건을 먼저 찾습니다.

- 비용 최우선인가, 품질 최우선인가
- 실시간 응답인가, 야간 배치인가
- 보안·규제 요구가 있는가
- 트래픽 규모는 어느 정도인가

이 조건이 곧 정답의 근거입니다. 같은 "리뷰 분류" 시나리오라도 "비용 최우선"이면 Haiku, "판정 실수 비용이 크다"면 다른 답이 됩니다.

선택지 문장에서는 두 가지를 조심합니다.

- "가장 적절한", "가장 효과적인"이라는 표현. 여러 개가 맞아 보여도 조건에 가장 잘 맞는 하나를 고르라는 뜻입니다.
- "항상", "모든 경우에" 같은 절대 표현이 들어간 선택지. 오답일 확률이 높습니다.

## 시간 배분

60문항 120분이니 1문항당 평균 2분입니다. 다만 시나리오 지문을 읽는 시간이 앞쪽에 몰립니다. 시나리오 하나(대략 10~15문항)를 20~30분 안에 끝낸다는 감각으로 갑니다.

- 1분 넘게 헤매는 문제는 표시하고 넘어갑니다.
- 뒤 문항이 앞 문항의 힌트가 되는 경우가 있어서, 한 바퀴 돈 뒤 돌아오면 풀리는 문제가 생깁니다.
- 마지막 15분은 검토에 씁니다.

한국에서 응시한다면 영어 지문을 시간 안에 읽는 연습이 별도로 필요합니다. 모의고사를 풀 때 시간을 재는 이유입니다.

## 공부 순서 (12주 모델)

교재가 제안하는 순서입니다. 총 100시간 정도로 잡혀 있습니다.

| 주차 | 내용 |
|---|---|
| 1~2주 | 환경 구축, Claude 기초, API 기초, 프롬프트 기초 |
| 3주 | 구조화 출력, Tool Use |
| 4~5주 | MCP 입문, MCP 설계, MCP 서버 구현 프로젝트 |
| 6~7주 | 에이전트 기초, 멀티 에이전트 |
| 8주 | 컨텍스트 관리, 신뢰성 |
| 9~10주 | Claude Code 기초, 확장(스킬·훅), CI/CD |
| 11주 | 멀티 에이전트 설계 프로젝트, 모의고사 절반 |
| 12주 | 모의고사 전체, 취약 도메인 복습, 응시 |

모의고사를 풀고 나서 다음 행동을 정하는 기준은 이렇습니다.

- 43문항 이상: 실전 응시
- 36~42문항: 가장 낮은 도메인의 본문으로 돌아가 복습한 뒤 재응시
- 그 아래: 전체를 한 번 더

가장 낮은 도메인이 배점 15%짜리 도메인 5라도 그 장으로 돌아가는 것이 맞습니다. 배점 높은 도메인 1만 복습하고 응시하는 것은 오답 선택지입니다.

## 핵심 정리

- 60문항 120분, 720/1000점 합격, 무응답은 오답. 영어.
- 도메인 1(27%)·3(20%)·4(20%)이 3분의 2, 도메인 5(15%)도 버릴 수 없다.
- 판단 기준 두 개: "반드시"는 결정적 해법(훅·게이트·스키마), 과잉 설계보다 최소 비용의 근본 대책.
- 시나리오에서 제약 조건(비용/품질, 실시간/배치, 규제, 규모)을 먼저 찾고 선택지를 본다.
- 모의고사 43/60이 응시 기준. 그 아래면 최저 도메인으로 돌아간다.
