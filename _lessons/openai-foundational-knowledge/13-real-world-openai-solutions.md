- 흔한 **OpenAI 솔루션 패턴** 알아보기
- 각 패턴이 해결하는 **고객 문제** 짚어 내기
- 한 솔루션 안에서 **제품 표면 · 역량 · 배포·운영 선택**을 구분하기
- 솔루션 패턴이 **산업과 비즈니스 기능**에 따라 어떻게 달라지는지 알아보기
- OpenAI 역량을 **측정 가능한 고객 성과**에 연결하기

고객은 제품 이름으로 시작하지 않아요. **느린 일, 흩어진 정보, 늦어지는 결정, 팀을 붙잡는 수작업**을 이야기하죠. 실전 솔루션은 **문제와 워크플로**에서 시작해요. 이 코스는 반복되는 솔루션 패턴을 알아보고, 산업마다 맞게 바꾸고, **Solution Pattern Snapshot**으로 문제 · 워크플로 · 기술 · 패턴 · 성과를 잇는 연습을 해요. 제품·모델 이름은 모두 **(강의 기준)** 이에요. 그리고 **Foundation 과정의 마지막 콘텐츠 레슨**이라, 끝에 레슨 1–12를 하나로 묶는 지도를 넣었어요.

## 1. 고객 문제에서 솔루션 패턴으로

### 고객 문제에서 시작하라

<div class="oa-eli">
  <span class="oa-eli__head">🩺 쉽게 말하면 — 보건실</span>
  <p>학생이 "두통약 주세요"라고 와도 보건 선생님은 바로 약을 주지 않아요. "언제부터? 잠은 잤니? 밥은?" 하고 <b>진짜 문제</b>를 먼저 물어보죠. 알고 보니 밤새 게임을 해서 졸린 거라면, 약이 아니라 휴식이 답이에요. 고객이 "ChatGPT 주세요", "API 주세요", "에이전트 주세요"라고 해도 마찬가지예요.</p>
</div>

고객은 "지식 지원 솔루션 패턴이 필요해요"라고 말하지 않아요. 이렇게 말하죠:

- "팀이 정보 찾는 데 시간을 너무 많이 써요."
- "고객 지원이 감당이 안 돼요."
- "소프트웨어 전달이 너무 느려요."
- "직원들이 같은 콘텐츠를 계속 다시 써요."
- "리서치와 분석이 너무 오래 걸려요."
- "결정을 늦추는 수작업 프로세스가 있어요."

이건 모두 **일이 처리되는 방식의 마찰 신호**예요. 문제에서 시작하면 제품 추천으로 **너무 빨리 뛰지 않게** 돼요.

| 고객이 묻는 것 | 실제로 필요할 수 있는 것 |
|---|---|
| ChatGPT | 더 넓은 워크플로 솔루션 |
| API | 먼저 더 명확한 사용 사례 정의 |
| 에이전트 | 그 일이 반복 가능하고, 거버넌스가 있고, 자동화 준비가 됐는지 이해 |

첫 질문: **"고객이 실제 업무에서 풀려는 문제는 무엇인가?"**

### 워크플로를 찾아라

**워크플로 = 일을 끝내는 데 관여하는 사람 · 작업 · 결정 · 정보 흐름 · 성과의 순서.** "고객 지원이 감당이 안 돼요"라는 넓은 문제 뒤에는 이런 워크플로가 있어요: 고객이 질문 제출 → 상담원이 정책·제품 정보 검색 → 복잡한 건 에스컬레이션 → 관리자가 패턴 검토 → 시스템이 해결 상태 추적. 그러면 AI가 도울 곳이 보여요: 빠른 정보 접근 · 더 나은 분류 · 답변 초안 · 사례 요약 · 에이전트형 인수인계 · 지식 베이스 개선.

  <div class="oa-card"><span class="oa-card__icon">👥</span><span class="oa-card__title">사람</span>누가 일하거나 경험을 받나?</div>
  <div class="oa-card"><span class="oa-card__icon">⚖️</span><span class="oa-card__title">결정</span>판단이나 승인이 중요한 곳은?</div>
  <div class="oa-card"><span class="oa-card__icon">🔄</span><span class="oa-card__title">정보 흐름</span>어떤 정보가 필요하고 어디서 오나?</div>
  <div class="oa-card"><span class="oa-card__icon">🎯</span><span class="oa-card__title">성과</span>고객이 개선하려는 결과는?</div>

그리고 레슨 9의 **세 가지 질문**을 따로 던져요:

| 레이어 | 질문 | 예 (강의 기준) |
|---|---|---|
| **제품 표면** | 사람·워크플로가 주로 어디서 일하나? | ChatGPT Chat · ChatGPT Work · Codex · API로 만든 앱·프로세스 |
| **역량** | 시스템이 무엇을 해야 하나? | 승인된 도구·연결 출처 · 검색 · 단계 조율 · 구조화 출력 · 일부 자동화 |
| **배포·운영** | 어디서 어떻게 돌고 통제되나? | 신원 · 권한 · 승인 · 보존 · 로깅 · 사람 검토 |

**솔루션 패턴 ≠ 제품.** 패턴은 문제와 개선되는 일의 **모양**이에요. 패턴이 분명해진 **뒤에** 표면 · 역량 · 배포·운영을 나눠요.

## 2. 실전 OpenAI 솔루션 패턴

각 예시에서 **고객 문제 · 영향받는 워크플로 · 표면과 역량 · 배포 고려 · 패턴 · 비즈니스 성과**를 찾아보세요. 목표는 제품 사실 암기가 아니라 **구성 요소가 어떻게 조합되는지** 보는 거예요.

### ① 지식·정보 접근

정보가 찾기 어렵거나 여러 시스템에 흩어져 있거나 문서에 갇혀 있을 때.

| 레이어 | 내용 (강의 기준) |
|---|---|
| 표면 | 직원용은 ChatGPT Chat · Work, 내장 경험은 API로 만든 앱 |
| 역량 | 승인된 도구·연결 출처 · 검색 · 요약 · 여러 단계면 에이전트형 조율 |
| 배포·운영 | 신원 · 출처 권한 · 승인 · 로깅 · 사람 검토 · 호스팅/내장 여부 |
| 성과 | 빠른 정보 접근 · 검색 시간 감소 · 의사결정 지원 · 일관성 · 더 나은 셀프서비스 |

> 예: 금융 서비스 어드바이저가 고객 질문에 더 자신 있게 답해야 하는데, 큰 내부 지식 베이스를 뒤지느라 시간이 많이 들어요. 목표는 "AI 도입"이 아니라 **관련 정보를 찾고 · 분명히 요약하고 · 고객용 후속 자료를 준비하되 리뷰와 감독을 유지하는 것**. 즉각적 질문은 **Chat**, 경계 있는 리서치 결과는 **Work**, 계속 모니터링이면 개인 책임은 **dot** · 팀 소유 일정·이벤트 프로세스는 **Team Task**. 반복 업무라면 **누구의 출처에 접근하나 · 어떤 변화가 업데이트 거리인가 · 누가 검토하나 · 언제 책임이 끝나나**를 정하고, 팀 프로세스는 어드바이저 개인 기록이 아니라 **팀의 설정된 연결**을 써요.

### ② 콘텐츠·커뮤니케이션 워크플로

이메일 · 메모 요약 · 공지 · 번역 · 톤 조정 · 발표 자료 · 마케팅 문구를 대규모로 만들고 다듬어야 할 때.

| 레이어 | 내용 (강의 기준) |
|---|---|
| 표면 | 반복 초안은 Chat, 위임된 여러 단계 창작은 Work, 내장이 필요하면 API 앱 |
| 역량 | 멀티모달 창작 · 승인된 도구·연결 출처 · 템플릿 · 반복 제작이면 에이전트형 조율 |
| 배포·운영 | 권한 · 승인 경계 · 보존 · 사용·공유 전 사람 검토 |
| 성과 | 생산성 · 빠른 제작 · 일관성 · 자신 있는 소통 · 반복 초안 시간 감소 |

> 예: 성장하는 회사가 직원 · 고객 · 파트너와 더 일관되게 소통하고 싶어요. 지식은 있는데 대상 · 톤 · 형식이 바뀔 때마다 글쓰기에 시간이 걸려요. Chat으로 초안 · 톤 · 번역 · 서식을 다듬고, Space가 켜져 있으면 **Page**에 편집 가능한 팀 업데이트를 둬요. 단, Page는 **결과물이지 최신으로 유지하는 프로세스가 아니에요** → **업데이트 담당자와 검토 주기**를 정하고, 공유 전에 **문구뿐 아니라 대상**도 검토해요(복사·요약된 정보는 원본이 제한돼 있어도 Page 독자에게 보여요). 가치는 AI가 소통 담당자를 **대체**하는 게 아니라 **대략적 의도 → 리뷰된 쓸 만한 소통**으로 더 빨리 가게 돕는 거예요.

### ③ 소프트웨어 전달·엔지니어링 워크플로

| 레이어 | 내용 (강의 기준) |
|---|---|
| 표면 | Codex |
| 역량 | 코드 이해·편집 · 테스트 · 리뷰 · 문서화 · 통합 · 소프트웨어 작업 전반의 에이전트형 조율 |
| 배포·운영 | 작업 공간 경계 · 권한·승인 · 버전 관리 · 테스트 · 사람 리뷰 |
| 성과 | 빠른 개발 주기 · 수작업 감소 · 엔지니어링 생산성 · 테스트·리뷰 지원 · 고가치 결정에 시간 |

> 예: 연구·엔지니어링팀이 복잡한 시뮬레이션 코드를 다뤄요. 진전은 코드 작성만이 아니라 아이디어 시험 · 가정 확인 · 구현 리뷰 · 신뢰성 개선에 달려 있어요. Codex가 코드 생성·개선 · 리뷰 지원 · 접근법 탐색을 돕고, **전문가가 검증하고 수용 여부를 정해요.** Codex Cloud에선 준비된 환경이 저장소 · 의존성 · 도구 · 승인된 접근을 주고 작업마다 자기 작업 공간이 있어요. 다른 기기에서 이어 가거나 리뷰어에게 넘기기 전에 **변경 · 돌린 검사 · 남은 한계**를 정리해요. **완료된 클라우드 실행 ≠ 병합·출시 승인.**

### ④ 리서치·분석 워크플로

시장 · 과학 · 재무 분석 · 정책 검토 · 경쟁 정보 · 운영 보고 · 전략 기획처럼 많은 정보를 통찰로 바꿔야 할 때.

| 레이어 | 내용 (강의 기준) |
|---|---|
| 표면 | 연구자용은 Chat · Work, 내장이 필요하면 API 앱 |
| 역량 | 리서치 · 승인된 도구·연결 출처 · 검색 · 비교 · 종합 |
| 배포·운영 | 출처 권한 · 출처 검증 · 사람 검토 · 보존 · 모니터링 |
| 성과 | 빠른 분석 · 통찰 · 명확한 종합 · 의사결정 지원 · 전문가 해석에 더 많은 시간 |

> 예: 전문 리서치팀이 복잡한 산업 트렌드를 이해해야 해요. 딥 리서치가 종합을 가속하지만 **출처 평가 · 전문성 적용 · 결과 활용 결정은 연구자**가 해요. 경계 있는 조사는 Chat · Work. 계속 모니터링이 필요해지면 **먼저 사람이 소유하나 팀이 소유하나**를 정하고 dot · Team Task를 고려해요 — **모든 반복 필요가 API 빌드를 요구하진 않아요.** 승인된 출처 · 업데이트 트리거 · **근거 날짜** · 검토 담당 · 멈출 조건을 정해 **오래된 결론이 새로 검증된 발견으로 오해받지 않게** 해요.

## 3. 기술을 조합해 완전한 솔루션 만들기

### 단일 제품 솔루션

주요 워크플로를 **하나의 주 표면**이 해결하면 집중된 솔루션이 적절해요(그래도 보조 역량과 통제는 솔루션의 일부예요).

| 표면 (강의 기준) | 지원하는 일 |
|---|---|
| **ChatGPT Chat** | 협업적 사고·창작: 초안 · 요약 · 브레인스토밍 · 분석 · 반복 개선 |
| **ChatGPT Work** | 결과 · 맥락 · 제약 · 승인 경계 · 검토 기준을 정의할 수 있는 위임된 여러 단계 지식 업무 |
| **Codex** | 소프트웨어 엔지니어링: 코드 이해 · 이슈 조사 · 구현 · 테스트 · 리뷰 · 문서 |
| **API로 만든 앱·프로세스** | 제품 · 포털 · 시스템 · 운영 워크플로 안의 내장·맞춤 AI |

> 예: 작은 운영팀이 대충 쓴 회의 메모를 깔끔한 내부 업데이트로 바꾸고 싶어요. 일은 협업적이고, 결과는 검토하기 쉽고, 다른 시스템과 통합할 필요가 없어요 → **ChatGPT Chat**만으로 충분할 수 있어요. 역량: 초안·요약. 운영: 적절한 워크스페이스 접근과 사람 검토. 패턴: 콘텐츠·커뮤니케이션 지원.

### 왜 솔루션 선택이 중요한가

표면 · 역량 · 배포·운영은 **서로 다른 질문에 답해요.** 너무 빨리 고르면 잘못 맞춰져요: 제품 안에 AI가 필요한 고객은 **API 경험**이, 신뢰할 지식이 필요한 고객은 **검색이나 승인된 연결 출처**가, 여러 단계에 걸친 일을 원하는 고객은 **에이전트형 조율과 명시적 승인 경계**가 필요할 수 있어요. 이건 **관련된 결정이지 서로 바꿔 끼울 제품 경로가 아니에요.**

| 고려사항 | 질문 |
|---|---|
| 제품 표면 | 사람·워크플로가 주로 어디서 일하나? |
| 역량 | 시스템이 무엇을 해야 하나? |
| 배포·운영 | 어디서 어떻게 돌고 통제되나? |
| 비즈니스 성과 | 어떤 측정 가능한 결과가 중요한가? |
| 준비·도입 | 사람 · 프로세스 · 정책 · 지원이 준비됐나? |
| 측정 | 솔루션이 작동하는지 어떻게 알 건가? |
| 소유·연속성 | 계속되는 일은 누가 소유하고, 결과는 누가 받나? |

**가장 효과적인 솔루션이 가장 복잡한 솔루션은 아니에요.** 워크플로 · 위험 수준 · 사용자 필요 · 의도한 성과에 맞는 **조합**이에요.

  <p>각각 <b>고객 문제 / 워크플로 / 제품 표면 / 역량 / 배포·운영 / 기대 성과</b>를 짧게 적고, 하나를 골라 <b>제안 소유자 · 경계 있는 일인지 계속되는 일인지 · 트리거 · 허용 출처나 연결 신원 · 결과 대상 · 사람 검토 지점</b>을 더하세요. 맞춤 앱이면 <b>런타임 선택</b>도. 빠진 세부는 고객 사실이 아니라 <b>질문</b>으로 남기기. 어떤 결정이 처음 고른 표면을 바꿀 수 있을까요?</p>

## 4. 산업별 솔루션 패턴

같은 패턴이 여러 산업에 나타나지만 **맥락 · 위험 · 이해관계자 · 성과**가 달라져요.

| 산업 | 특징 | 자주 보이는 패턴 | 예시 (강의 기준, 의역) |
|---|---|---|---|
| 💰 **금융 서비스** | 복잡한 정보 · 규제 워크플로 · 정확성과 신뢰에 대한 높은 기대 | 지식 업무 · 분석 · 고객 서비스 · 운영 효율 | 어드바이저가 검색 대신 고객 대화 준비에 시간을 쓰게. 성과는 "빠른 검색"이 아니라 **정보에 근거하고 규정을 지키는 적시 고객 서비스**. 표면 Chat·Work / 역량 승인된 지식 접근·검색·요약 / 운영 권한·출처 품질 확인·사람 검토·모니터링 |
| 🏥 **의료·생명과학** | 대량 정보 · 전문 용어 · 운영 제약 · 민감한 워크플로 | 정보 접근 · 리서치 · 운영 프로세스 | 소아 병원이 연구·임상·행정팀용 보안 내부 ChatGPT 환경 도입(거버넌스·모니터링·평가 포함). 공급망에서 송장 접수·라우팅·응답 지원 |
| 💼 **전문 서비스** | 리서치 · 분석 · 고객 납품물 · 협업 · 전문가 판단 | 리서치 · 문서 작성 · 협업 · 생산성 | 낯선 시장을 빠르게 이해해 고객 논의용 관점 준비. 표면 Chat·Work / 역량 리서치·승인된 연결 출처·종합·문서 작성 / 운영 고객 정보 권한·출처 검증·사람 검토. 패턴: **방어 가능한 근거**를 갖춘 리서치·분석 |

### 의료 사례의 숫자를 올바르게 읽기

<div class="oa-eli">
  <span class="oa-eli__head">🏆 쉽게 말하면 — 학교 전체 성적 vs 한 과목</span>
  <p>"우리 학교가 작년보다 평균 10점 올랐대!"를 듣고 "그럼 수학이 10점 올랐구나"라고 하면 틀려요. 그건 <b>학교 전체 프로그램</b>의 결과예요. 그리고 "옆 학교도 10점 오르겠네"라고 예측할 수도 없죠.</p>
</div>

- 소아 병원은 **50개 이상의 자동화** 전체에서 약 **60,000시간** 절약을 보고했어요 (강의 기준).
- 이 숫자는 **자동화 프로그램 전체**에 해당해요 — **송장 워크플로 하나의 결과가 아니고**, 다른 병원의 결과 **예측으로 쓰면 안 돼요.**
- AI는 텍스트 초안만이 아니라 **여러 단계 프로세스를 움직이는 데** 쓰였어요.
- **운영 사례이지 AI 임상 진단 사례가 아니에요.** 이 산업에선 정확성 · 출처 품질 · 프라이버시 · 규제 기대 · 사람 검토가 핵심이에요.

## 정리

- 실전 솔루션은 **제품이 아니라 고객 문제**에서 시작한다. 워크플로는 **사람 · 결정 · 정보 흐름 · 성과**를 드러낸다.
- **솔루션 패턴 ≠ 제품.** 지식 지원 · 워크플로 가속 · 소프트웨어 전달 · 리서치·분석 · 콘텐츠 생성 · 고객 서비스 증강은 **문제의 모양**이고, 그다음에 **표면 · 역량 · 배포·운영**을 나눈다.
- 주요 워크플로를 한 표면이 해결하면 **단일 솔루션**으로 충분하다. 조합 솔루션도 **결정을 레이어별로 분리**한다. **가장 효과적인 솔루션 ≠ 가장 복잡한 솔루션.**
- 계속되는 일엔 **소유자와 시간 경계**, 공유 Page엔 **대상과 갱신자**, 클라우드 작업엔 **리뷰 근거**. **맞춤 UX ≠ 런타임, 이벤트 트리거 ≠ 행동 권한.**
- 같은 패턴도 **산업 맥락**(위험 · 이해관계자 · 출처 품질 · 리뷰 기대 · 성과)에 맞게 조정한다. 산업 라벨로 제품을 자동 선택하지 않는다. 보고된 숫자는 **범위를 정확히** 읽고 **예측으로 쓰지 않는다.**
- Foundation 전체를 꿰는 순서: **고객 문제 → 워크플로 → 제품 표면 → 역량 → 배포·운영 → 솔루션 패턴 → 성과.** 사실 · 가설 · 열린 질문을 구분하며, 고객이 알아볼 수 있는 성과에 연결하는 **솔루션 지향 파트너**처럼 생각한다.
