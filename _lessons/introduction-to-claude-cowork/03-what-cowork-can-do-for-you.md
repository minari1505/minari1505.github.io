## 학습 목표

- Cowork에 맞는 세 가지 작업 패턴(**다단계 · 파일 기반 · 다중 도구**) 알아보기
- `/schedule`로 **예약 작업(scheduled task)** 설정하기
- 휴대폰이나 아무 브라우저에서 Cowork 작업을 시작하거나 확인하기

## 1. Cowork에 맞는 작업의 세 가지 패턴

<div class="oa-eli">
  <span class="oa-eli__head">🧳 쉽게 말하면</span>
  <p>"물 한 잔 줘"는 그냥 부탁하면 되지만, <b>"출장 준비해 줘"</b>는 달라요. 항공권을 알아보고, 서류를 챙기고, 일정표를 만들어야 하죠. 단계가 여럿이고, 실제 서류가 오가고, 여러 곳을 들러야 하는 일이 Cowork에 맡길 일이에요.</p>
</div>

모든 작업이 Cowork에 맞는 건 아니에요. 맞는 작업을 알아볼 수 있을 때 더 많이 얻어요. 대부분은 다음 세 패턴으로 설명돼요.

  <div class="oa-card"><span class="oa-card__icon">🪜</span><span class="oa-card__title">패턴 1 · 다단계</span>모으고 → 비교하고 → 초안 쓰고 → 포맷하는 arc 전체를 한 프롬프트로 맡겨요</div>

  <div class="oa-card"><span class="oa-card__icon">🧰</span><span class="oa-card__title">패턴 3 · 여러 도구</span>이미 쓰는 시스템들을 가로질러 계획하고 실행해요</div>
</div>

### 패턴 1: 다단계 작업

여러 단계가 필요한 작업이면 좋은 후보예요. 한 번의 프롬프트로 Claude가 맥락을 모으고, 소스를 비교하고, 추가 조사를 하고, 요약 초안을 쓰고, 결과물을 포맷해요.

- 한 주치 고객 피드백 이메일을 테마별로 분류 (각 테마 예시 인용 포함)
- 세 보고서와 스프레드시트에서 수치를 뽑아 하나의 인터랙티브 대시보드로 조립

**진행 패널(Progress panel)**: Cowork는 작업을 단계로 쪼개 실행 중 각 단계를 보여 줘요. 지켜봐도 되고, 끝난 뒤 돌아와도 돼요.

<ol class="oa-flow">
  <li><strong>Read</strong>소스 파일 읽기</li>
  <li><strong>Compare</strong>비교하고 묶기</li>
  <li><strong>Draft</strong>결과물 초안</li>
  <li><strong>Format</strong>포맷 맞추기</li>
  <li><strong>Self-review</strong>스스로 검토</li>
</ol>

### 패턴 2: 실제 파일에 사는 작업

목표가 실제 산출물(Word 문서, 스프레드시트, 덱, PDF)을 원하는 형식으로 저장하는 것이면 잘 맞아요. 입력도 실제 파일이라, Claude가 폴더의 기존 파일을 읽고 수정해 다시 저장해요. Claude는 언제든 새 문서 초안을 쓸 수 있지만, Cowork는 **이미 있는 파일** 위에서도 작업해요.

- 표준 템플릿과 회의록에서 끌어온 포맷된 고객 제안서
- 원시 스프레드시트에서 조립한 월간 지표 보고서 (차트 포함)

### 패턴 3: 여러 도구에 걸친 작업

이미 쓰는 시스템(Gmail, Slack, M365, 캘린더, CRM)에 걸친 작업이에요. Claude가 커넥터(Claude를 내 앱에 연결하는 integration)로 접근해 맥락을 모으고 행동해요.

      <li>전체 시퀀스를 <b>하나의 위임</b>으로 실행해요</li>

- 캘린더 초대 · 참석자 · 회의록 기반으로 Outlook 후속 이메일 작성
- 런칭에 대한 Slack의 모든 언급을 검색해 업데이트로 종합

세 패턴을 관통하는 줄기는 같아요: 예전에는 단계 · 파일 · 도구를 **내 머릿속에서 저글링**해야 했던 일을 이제 하나의 작업으로 넘길 수 있어요. 그 모양이 보이면 Cowork에 주세요.

## 2. 예약 작업 (Scheduled tasks)

<div class="oa-eli">
  <span class="oa-eli__head">⏰ 쉽게 말하면</span>
  <p>매일 아침 커피를 직접 내리는 대신 <b>타이머 달린 커피 머신</b>을 맞춰 두는 것과 같아요. 한 번 설정하면 정해진 시간에 알아서 돌아요.</p>
</div>

작업을 한 번 설정해 일정(cadence)에 맞춰 반복 실행해요. 설정 방법은 두 가지예요.

| 방법 | 순서 |
|---|---|
| **처음부터** | `/schedule` 입력 → 작업과 주기를 설명 → Claude가 프롬프트 초안 작성 → 검토 · 수락 |
| **더 자연스러운 방법** | Cowork에서 작업을 한 번 실행 → 결과가 맞는지 확인 → `/schedule`로 그 과정을 반복 작업으로 전환 → 주기 지정 → 프롬프트 검토 후 수락 |

주기는 **매시간(hourly) · 매일(daily) · 평일(weekdays) · 수동(manual)** 중에서 정해요.

### 예약 작업은 어디서 도나요?

작업에 무엇이 필요한지에 따라 달라요.

| 작업이 쓰는 것 | 실행 위치 | 컴퓨터가 켜져 있어야 하나요? |
|---|---|---|
| **커넥터만** | 정해진 시간에 **원격으로** 실행 | 아니요 |
| **내 컴퓨터의 파일이나 앱** | **내 컴퓨터에서** 실행 | 네. 그 시간에 desktop app이 열려 있어야 해요 |

> 내 컴퓨터에서 도는 작업인데 예약 시간에 노트북이 닫혀 있거나, 잠자기 상태거나, 꺼져 있으면, 돌아왔을 때 Claude가 바로 작업을 집어 들고 **지연됐다고 알려 줘요.**

강의 영상은 이전 버전의 앱에서 녹화돼서 일부 화면이 다르게 보일 수 있어요. 예약 작업을 설정하는 방법은 같아요.

### 예약할 만한 아이디어

- **금요일 오후 주간 리뷰**: 한 주 동안 출시된 것, Slack이나 Teams에서 내린 주요 결정 recap, 다음 주 작업 preview
- **매월 1일 지표 롤업**: 스프레드시트에서 끌어온 월간 metrics
- **아침 브리핑**: 캘린더의 회의에 대해, 폴더의 과거 회의록과 이메일 스레드에서 필요한 맥락을 끌어와요

## 3. 자리를 떠나서 일하기

<div class="oa-eli">
  <span class="oa-eli__head">📱 쉽게 말하면</span>
  <p>출근길에 세탁소에 전화로 맡겨 두고 <b>퇴근길에 찾아가는 것</b>과 같아요. 맡기는 곳과 찾는 곳이 달라도 한 건의 세탁물이에요.</p>
</div>

지금까지는 책상에서 시작하는 작업과 Claude가 일정에 맞춰 돌리는 작업을 봤어요. 세 번째는 **컴퓨터 근처에 없을 때 시작하는 작업**이에요.

Cowork는 **웹과 Claude 모바일 앱**에서도 동작해요. 이렇게 시작한 작업은 내 컴퓨터가 아니라 **원격으로** 돌기 때문에, 켜 두거나 깨워 둘 것이 없어요.

<ol class="oa-flow">
  <li><strong>휴대폰에서 시작</strong>출근길에 작업을 맡겨요</li>
  <li><strong>아무 브라우저에서 확인</strong>그날 중간에 진행 상황을 봐요</li>
  <li><strong>책상에서 받기</strong>결과물이 기다리고 있어요</li>
</ol>

하나의 session이 여러 기기에서 이어지는 거예요. 따로따로인 세 작업이 아니에요.

### 의존하기 전에 알아 둘 두 가지

| 알아 둘 것 | 의미 |
|---|---|
| **커넥터에는 닿지만 로컬 폴더에는 못 닿아요** | 웹이나 휴대폰에서 시작한 작업은 내 컴퓨터의 폴더를 못 봐요. 내 컴퓨터에만 있는 파일이 필요하면 desktop app에서 시작해요 |
| **작업은 시작한 곳에 머물러요** | 작업이 일어나는 곳을 바꾸려면 새 작업을 시작해요 |

> 조직이 Claude를 관리해 주는 경우, 이 기능을 켤지는 **admin이 결정**해요.

### 예시

- 출근길에 오늘 고객 통화에 지난 분기 support ticket 1페이지 요약이 필요하다는 게 떠올라요. 휴대폰의 Claude 앱에서 Cowork에게 연결된 support 도구에서 그 분기의 ticket을 끌어와 1페이지를 만들어 달라고 해요. 통근하는 동안 시작되고, 책상에 도착하면 초안을 검토해요.
- 오프사이트 중에 벤더가 수정된 계약 조건을 보내요. 휴대폰에서 Cowork에게 Drive에 있는 작년 계약과 비교해 모든 변경을 나열해 달라고 해요. 끝나면 휴대폰이나 아무 브라우저에서 비교 결과를 읽어요.

### 이전 버전 강의에 있던 Dispatch 설명

아래는 이 노트를 처음 작성할 때 강의에 있던 내용이에요. 현재 강의 페이지 본문에는 **Dispatch**라는 이름이 없고 위의 "웹 · 모바일에서 시작하면 원격 실행" 설명으로 바뀌어 있어서 따로 모아 둬요. 지금도 그대로인지는 확인하지 못했어요.

- Dispatch는 컴퓨터에서 떨어져 있을 때의 작업을 다뤘어요. Claude 모바일 앱에서 작업을 지정하면, 작업은 **데스크톱에서**(같은 파일 · 커넥터 · 권한으로) 실행되고, 끝나면 푸시 알림을 받았어요.
- 데스크톱이 켜져 있고 로그인 · Cowork 열림 상태일 때만 동작했어요.
- 당시에는 research preview로 Pro · Max plan에서 제공됐고, Enterprise는 아직 없을 수 있으며 활성화된 곳에서는 IT 관리자가 설정한다고 안내했어요.

## 4. 종합 — 판단은 사용자 몫

다단계 · 파일 기반 · 다중 도구 패턴은 **무엇을** 넘길 가치가 있는지 알려 줘요. 예약 작업과 모바일 앱은 넘기는 일이 **책상에 앉을 때까지 기다릴 필요가 없다**는 걸 뜻해요.

판단은 여전히 사용자에게 있어요. Claude는 계획하고, 실행하고, 물어봐요. 무엇을 보내고, 공유하고, 내보낼지는 사용자가 정해요.

## 정리

- **다단계 · 파일 기반 · 다중 도구**, 이 세 패턴이 무엇을 맡길지 알려 줘요.
- Cowork는 작업을 단계로 쪼개 **Progress panel**에 보여 줘요. 지켜봐도 되고 나중에 돌아와도 돼요.
- **예약 작업**은 `/schedule`로 만들어요. 커넥터만 쓰면 원격으로 돌고, 로컬 파일이나 앱이 필요하면 desktop app이 열려 있어야 해요.
- **웹 · 모바일**에서 시작한 작업은 원격으로 돌고, 커넥터에는 닿지만 로컬 폴더에는 닿지 못해요. 작업은 시작한 곳에 머물러요.
- 판단은 여전히 사용자 몫이에요. Claude는 계획 · 실행 · 질문하고, 무엇을 보내고 공유할지는 사용자가 정해요.

다음 레슨에서는 고른 작업을 프롬프트부터 완성된 결과물까지 처음부터 끝까지 위임해 봐요.
