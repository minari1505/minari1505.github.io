## Activity 1 — ChatGPT가 맞는지 확인하기 (레슨 1·2 적용)

**목표**: 어떤 제품 경험이 워크플로우에 가장 맞는지 판단. **ChatGPT를 너무 일찍 꺼내지 않기.**

| 먼저 밝힐 것 | 연결되는 개념 |
|---|---|
| 누가 일하나? | 워크플로우 지도의 User (레슨 2) |
| 어떤 워크플로우가 마찰을 만드나? | 업무 고통에서 출발 (레슨 1) |
| 어떤 입력을 쓰나? | Inputs, 운영 맥락 |
| 어떤 결과물이 필요하고, 누가 쓰거나 검토하나? | primary-output test (레슨 1) |
| 어디가 느리고·들쭉날쭉하고·위험한가? | 마찰 지점 (레슨 2) |
| Chat 협업 / Work 위임 / Codex / API / 조합 중 무엇? | 경로 선택 (레슨 1) |
| 전체 추천 전에 무엇을 검증해야 하나? | Validation fit (레슨 1) |

<div class="oa-eli">
  <span class="oa-eli__head">💬 이런 식으로 물어볼 수 있어요 (예시, 내 말로 정리)</span>
  <p>• "중요한 고객 미팅 전에 팀이 실제로 어떤 순서로 준비하세요? 어디서 시간이 제일 많이 드나요?"<br>• "그 브리핑은 누가 만들고, 누가 마지막으로 확인하나요?"<br>• "어떤 자료를 참고하세요? 그중 고객 정보가 들어 있는 건 어떤 거죠?"<br>• "팀원이 대화하며 같이 다듬길 원하세요, 아니면 초안을 맡기고 검토만 하길 원하세요?"</p>

## Activity 3 — 준비도 검증과 다음 단계 (레슨 4 적용)

<div class="oa-eli">
  <span class="oa-eli__head">🍰 쉽게 말하면</span>
  <p>레시피가 훌륭하다고(강한 추천) 바로 100인분 케이크를 주문받으면 안 돼요. 재료가 다 있는지, 오븐이 되는지, 맛볼 사람은 누구인지 먼저 확인하죠. <b>강한 추천 ≠ 배포 준비 완료</b>예요.</p>
</div>

### 탐색할 질문

- 우선 워크플로우가 충분히 **구체적**인가?
- 어떤 **자료·비즈니스 맥락**에 의존하나?
- **접근·권한·검토 기대치**가 명확한가?
- **IT·보안** 등 다른 이해관계자가 들어와야 하나?
- 워크플로우가 **유용하다는 증거**와 **책임 있게 쓰인다는 증거**는 각각 무엇인가?
- 다음 단계는 추가 디스커버리 / 워크플로우 검증 / 이해관계자 정렬 / 인수인계 중 무엇인가?

각 공백마다 **누가 확인할지**, 다음 대화에 **어떤 증거가 필요한지**를 정해요.

### 최종 추천에 들어갈 7가지

| # | 요소 | Harbor & Finch 예 (요약) |
|---|---|---|
| 1 | 추천 ChatGPT 경험 | ChatGPT Work |
| 2 | 우선 워크플로우 | 고객 미팅 전 브리핑 준비 |
| 3 | AI 지원 작업 패턴 | 승인된 자료 종합 → 검토용 초안 (위임형) |
| 4 | 비즈니스 가치 | 준비 속도·일관성·누락 감소 (검증할 가설) |
| 5 | 신뢰·검토 고려 | 고객 정보 접근 경계, 고객 대면 전 사람 검토 |
| 6 | 준비도 공백 | 승인 자료 목록, IT·보안 참여, 기준선 미정 등 |
| 7 | 다음 행동 | 증거가 지지하는 단계 (예: 관계자와 워크플로우 검증 세션) |

> 목표는 기회를 실제보다 **더 성숙해 보이게 만드는 것이 아니라**, 증거가 지지하는 다음 단계를 추천하는 것이에요.

## 정리

- 연습 코스의 패턴: **워크플로우에서 시작 → 솔루션 적합성 시험 → 비즈니스 가치 연결 → 검토·거버넌스를 일찍 꺼내기 → 이야기가 충분히 명확할 때만 진행 추천.**
- Activity 1은 "어떤 경험이 맞나", Activity 2는 "왜 이 워크플로우부터", Activity 3은 "증거가 어디까지 지지하나"를 연습한다.
- 최종 추천에는 경험·워크플로우·작업 패턴·가치·신뢰 고려·준비도 공백·다음 행동 7가지가 들어간다.
- 레슨 1~4의 산출물(fit-check → 워크플로우 추천문 → 포지셔닝 문장 → 인수인계 요약)은 **한 고객 대화의 네 단계**다.
